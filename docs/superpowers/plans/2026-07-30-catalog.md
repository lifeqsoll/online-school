# Catalog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Catalog on the existing NestJS Foundation: courses/modules/lessons, free/paid(mock)/grant enrollment, MinIO video upload + external playable URLs, curator impersonation, and test UI/Postman/e2e.

**Architecture:** Extend the modular monolith. Postgres remains source of truth; MinIO provides S3-compatible storage in Docker; `PaymentProvider` interface with `MockPaymentProvider` only (`PAYMENT_PROVIDER=mock`); YooKassa webhook route stubbed. Access checks via shared `CourseAccessService`.

**Tech Stack:** NestJS 11, Prisma 7 (+ adapter-pg), MinIO (`@aws-sdk/client-s3`, `@aws-sdk/s3-request-presigner`), multer/`FileInterceptor`, existing JWT/RBAC/Redis stack, Jest e2e, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-07-30-catalog-design.md`

## Global Constraints

- Backend-first; only extend `public/` test HTML — no React production app.
- Free course = `priceCents === 0`; paid requires `Payment SUCCEEDED` (mock confirm) before enrollment.
- Grant enroll allowed for course curator and admin without payment.
- `PAYMENT_PROVIDER=mock` only in this slice; YooKassa route returns not-configured.
- Videos: `UPLOADED` (MinIO `storageKey`) and/or `EXTERNAL_URL` (https playable: mp4 / youtube / vimeo).
- Curator impersonation only for students enrolled in curator’s courses; admin unchanged.
- Follow existing Foundation patterns (`CryptoService`, `AuditService`, `@Public`, guards).
- Do not implement Homework/Neo4j/real YooKassa SDK.
- TDD where practical; commit after each task on `feature/foundation-auth` (or `feature/catalog` if branched).
